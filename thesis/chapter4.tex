\chapter{Experimental Evaluation}
\label{ch:results}

This chapter presents the experimental evaluation of AnyUp3D.
Section~\ref{sec:setup} describes the experimental setup, including hardware, backbone, model configuration, and training details.
Section~\ref{sec:convergence} provides a qualitative and quantitative analysis of training convergence by comparing early and late checkpoints.
Section~\ref{sec:temporal} evaluates temporal feature consistency against the frame-independent 2D~AnyUp baseline across the full DAVIS~2017 validation set.
Section~\ref{sec:jf} measures the downstream impact of AnyUp3D features on video object segmentation using the standard $\mathcal{J}\&\mathcal{F}$ metric.
Section~\ref{sec:cost} quantifies the computational price of the temporal extension, benchmarking parameter count, inference latency, and peak GPU memory against the frame-independent 2D baseline.
Finally, Section~\ref{sec:discussion} discusses the results in aggregate, examines the two clips where AnyUp3D underperforms bilinear, and acknowledges the evaluation's limitations.


% ────────────────────────────────────────────
\section{Experimental Setup}
\label{sec:setup}

% ── 4.1.1 Hardware & Software ──
\subsection{Hardware and Software}

All experiments were conducted on Google Colab.
The implementation uses PyTorch 2.x with CUDA, and models were run in mixed-precision (\texttt{float16}) where supported.

% ── 4.1.2 Backbone ──
\subsection{Backbone}

We use VideoMAE~\cite{videomae} (ViT-B/16, pretrained on Kinetics-400~\cite{kay2017kinetics}) as the primary spatiotemporal feature extractor and as the backbone AnyUp3D is fine-tuned against during training.
VideoMAE processes 16 input frames using a tubelet size of~2, producing $T' = 8$ temporal tokens.
Each frame is patchified at $16 \times 16$, yielding a spatial resolution of $14 \times 14$ per temporal slice.
The resulting feature tensor has shape $(1, 768, 8, 14, 14)$, that is, 768-dimensional features at $8 \times 14 \times 14$ spatiotemporal positions.

We chose VideoMAE because it produces genuinely spatiotemporal tokens: its tubelet embedding jointly encodes pairs of adjacent frames, so the features at each position already carry short-range temporal context.
This makes it a natural input for AnyUp3D, which extends this temporal structure to the upsampled resolution.

VideoMAE is used for Experiments~1 and~2 (Sections~\ref{sec:convergence}, \ref{sec:temporal}).
Experiment~3 (Section~\ref{sec:jf}) additionally evaluates AnyUp3D on Video Swin-T features, a backbone distinct from VideoMAE, as a deliberate zero-shot generalization test described there.

% ── 4.1.3 AnyUp3D Configuration ──
\subsection{AnyUp3D Configuration}

\paragraph{3D Convolutions.}
AnyUp3D replaces the 2D depth-wise convolutions in the value projection with 3D convolutions using a kernel of size $3 \times 1 \times 1$ (temporal $\times$ height $\times$ width) --- that is, a temporal extent of $t_k = 3$ over a $1 \times 1$ spatial footprint.
This allows each feature position to directly aggregate information from its immediate temporal neighbors during the projection step, without requiring the attention mechanism to span across time, and without enlarging the spatial receptive field inherited from the 2D model.

\paragraph{3D Spatiotemporal Attention.}
The cross-attention window covers a local spatial neighbourhood determined by a window ratio of $0.1$ relative to the spatial resolution, matching the 2D~AnyUp default.
Along the temporal axis the window spans $w_t = 4$ adjacent slices, chosen as an absolute frame count (rather than a resolution-relative ratio) to keep the receptive field consistent across T-curriculum stages, as detailed in Chapter~3.

Additional hyperparameters, query/key dimension $d_{qk} = 128$, four attention heads, match the 2D~AnyUp defaults.
Together the 3D convolutions capture local short-range temporal continuity, while the 3D attention enables the model to align spatiotemporal features with the high-resolution RGB guide.

% ── 4.1.4 Training ──
\subsection{Training Details}

AnyUp3D was trained for 6{,}000 steps using the AdamW optimizer with a learning rate of $2 \times 10^{-4}$.
Model weights were initialised from the pretrained 2D~AnyUp checkpoint, providing a strong spatial upsampling prior before any temporal training begins.
Training followed the T-curriculum strategy described in Chapter~3: beginning with $T\!=\!2$ frames to warm up the spatial upsampling pathway, then increasing to $T\!=\!4$ at step 5{,}000.
The third stage ($T\!=\!8$, scheduled to activate at step 15{,}000) was not reached within the current training run; completing this stage is left as future work that would expose the model to the full temporal resolution used at evaluation time.
The objective function combines four loss terms: $\mathcal{L}_\text{cos-mse}$, $\mathcal{L}_\text{input-consistency}$, $\mathcal{L}_\text{self-consistency}$, and $\mathcal{L}_\text{temporal-consistency}$ with RGB-difference gating, as detailed in Section~\ref{sec:losses} of Chapter~3.

% ── 4.1.5 Evaluation Dataset ──
\subsection{Evaluation Dataset}

All evaluations use the DAVIS~2017 validation set~\cite{davis2017}, a standard video object segmentation benchmark containing 30 video clips with pixel-level ground-truth annotations.
DAVIS~2017 is well suited for this evaluation: its clips are short enough to process on a T4 GPU, cover diverse motion types (from slow camera pans to fast athletic movements), and provide ground-truth masks that enable both quantitative and qualitative assessment.

% ── 4.1.6 Baselines ──
\subsection{Baselines}

We compare AnyUp3D against two baselines:

\paragraph{Bilinear upsampling.}
The VideoMAE feature tensor at $14 \times 14$ spatial resolution is upsampled to $224 \times 224$ using trilinear interpolation, independently per channel.
This baseline requires no learned parameters and represents the simplest possible spatial upsampling strategy.

\paragraph{2D AnyUp (frame-independent).}
The pretrained 2D~AnyUp model~\cite{anyup} is applied independently to each frame.
Each temporal slice of the VideoMAE feature tensor is treated as a separate image-level feature map and upsampled using the original AnyUp architecture with no temporal context.
This baseline isolates the contribution of the temporal extension: any improvement of AnyUp3D over this baseline is attributable to the 3D temporal modeling rather than the spatial cross-attention mechanism, which both models share.

\section{Experiment 1: Training Convergence}
\label{sec:convergence}

Before evaluating AnyUp3D on benchmark metrics, we verify that the model learns meaningful spatial structure during training.
We do so by comparing the upsampled features produced by an early checkpoint (step~250) against the final checkpoint (step~6{,}000), applied to the same input video.

% ── 4.2.1 Setup ──
\subsection{Setup}

A short video clip is processed through VideoMAE to produce features of shape $(1, 768, 8, 14, 14)$.
Both checkpoints receive the same low-resolution features and the same RGB guide video, and produce upsampled output at $224 \times 224$ spatial resolution.
We visualize the output using PCA (Principal Component Analysis): the top three principal components of the 768-dimensional feature vectors are mapped to RGB channels, with PCA fitted jointly across all frames to ensure color consistency over time.

In addition to this qualitative visualisation, we compute a quantitative feature-fidelity metric.
For each frame, we spatially average-pool both the native $14 \times 14$ low-resolution VideoMAE feature map and the $224 \times 224$ AnyUp3D output down to a single 768-dimensional vector, and measure the cosine similarity between the two.
This captures whether the $16\times$ spatial upsampling preserves the semantic content of the original feature, independent of pixel-level spatial detail.

\section{Experiment 2: Temporal Feature Consistency}
\label{sec:temporal}

The central claim of AnyUp3D is that jointly processing the temporal dimension produces more temporally coherent features than applying a 2D upsampler independently to each frame.
This experiment tests that claim directly.

% ── 4.3.1 Setup ──
\subsection{Setup}

For each of the 30 video clips in the DAVIS~2017 validation set, we extract VideoMAE features and upsample them using two methods: (1)~2D~AnyUp applied independently to each frame, and (2)~AnyUp3D applied to the full spatiotemporal volume.
We then measure temporal consistency as the mean cosine similarity between the feature maps of adjacent frames.
Concretely, for an output tensor of shape $(1, C, T', H, W)$, we compute:
\begin{equation}
    \text{TemporalSim} = \frac{1}{T'-1} \sum_{t=0}^{T'-2}
    \text{cos}\!\left(\mathbf{q}_t,\, \mathbf{q}_{t+1}\right),
    \label{eq:temporal_sim}
\end{equation}
where $\mathbf{q}_t \in \mathbb{R}^{C \cdot H \cdot W}$ is the flattened feature map at time step~$t$.
Higher values indicate greater temporal stability, that is, features that change smoothly between adjacent frames rather than flickering.

\section{Experiment 3: Downstream Video Object Segmentation}
\label{sec:jf}

While Experiment~2 measures feature-level consistency, it does not directly assess whether the upsampled features are useful for a downstream task.
This experiment evaluates AnyUp3D features in a practical video object segmentation pipeline using the standard $\mathcal{J}\&\mathcal{F}$ metric.

% ── 4.4.1 Setup ──
\subsection{Setup}

We evaluate AnyUp3D's downstream utility using non-parametric label propagation, following the protocol of Jabri et al.~\cite{jabri2020} (\textit{Space-Time Correspondence as a Contrastive Random Walk}), with the context-window design of Caron et al.~\cite{caron2021dino} (DINO).
Under this protocol, the ground-truth object mask is given only for the first frame of each clip; masks for all subsequent frames are propagated by attending, in feature space, from each query location to its most similar locations in a small set of context frames.
No head is trained and no parameters are learned or fine-tuned at any stage of this experiment: the propagated masks depend entirely on the similarity structure of the frozen upsampled features.
This makes the evaluation a direct, unconfounded test of feature quality, any difference in resulting mask accuracy between AnyUp3D and bilinear upsampling is attributable to the features themselves, not to differences in a separately-trained downstream component.

For each of the 30 DAVIS~2017 validation clips, a Video Swin Transformer (Swin-T, Kinetics-400 pretrained) extracts spatiotemporal features from frames sampled at approximately 2\,frames per second.
These features are upsampled to $56 \times 56$ resolution using either AnyUp3D or bilinear interpolation, producing the two conditions compared in this experiment.
$56 \times 56$ was chosen as the propagation resolution: high enough to resolve object boundaries, while keeping the $\mathrm{O}(N^2)$ pairwise affinity computation between all query and context locations tractable on a single T4 GPU.
The evaluated checkpoint is \texttt{anyup3d\_step6000.pth}, the latest available training state at the time of this experiment.

As in Experiment~2, features are extracted with Video Swin-T rather than VideoMAE, the backbone AnyUp3D was fine-tuned against during training.
This is a deliberate choice, not an oversight: it tests whether AnyUp3D's upsampling generalizes to a backbone it has never seen, which is the central claim motivating its architecture.
The Learned Feature Unification (LFU3D) module maps an arbitrary backbone's channel dimensionality onto a fixed internal representation, and the temporal cross-attention mechanism operates on that representation independently of the source encoder's identity; if this design achieves genuine backbone-agnostic upsampling rather than statistics specific to VideoMAE, it should improve propagated mask quality even under this backbone shift.
This experiment is therefore best understood as a zero-shot cross-backbone generalization test, using label propagation as a training-free lens onto feature quality.

For each frame $t > 0$, the propagation context consists of frame $0$ (a fixed anchor, to prevent long-term drift) together with the $N_{\text{last}} = 6$ most recently propagated frames, following the DINO evaluation protocol.
Query–context affinities are computed as cosine similarity scaled by a softmax temperature $\tau = 0.07$; only the top $k = 7$ most similar context locations per query are retained before the softmax, with all others masked out.
Labels are propagated as a weighted combination of context labels under these attention weights, and multi-object masks are obtained by taking the arg-max over the propagated per-object channels.

We evaluate on all 30 clips of the DAVIS~2017 validation set using the standard $\mathcal{J}\&\mathcal{F}$ score, where $\mathcal{J}$ measures region overlap (Jaccard index) and $\mathcal{F}$ measures contour accuracy, under the semi-supervised protocol (first-frame mask given, all subsequent frames predicted).

It is important to note that the absolute $\mathcal{J}\&\mathcal{F}$ scores in this experiment are not directly comparable to dedicated video object segmentation methods (e.g., STM (Space-Time Memory Networks)~\cite{stm}, XMem~\cite{xmem}), which combine learned matching networks with substantial training on video segmentation data and typically exceed $0.80$ on DAVIS~2017.
Non-parametric label propagation on generic, frozen video-encoder features is a much simpler and strictly training-free baseline.
The purpose of this experiment is not to compete with dedicated VOS methods, but to measure whether AnyUp3D features carry more spatially discriminative information than bilinearly upsampled features under an evaluation protocol with no trainable components at all.

The result is notable given the conditions under which it was obtained: AnyUp3D was evaluated zero-shot on Swin-T features, a backbone distinct from VideoMAE, the encoder it was fine-tuned against, and training ran for only 6{,}000 steps (versus 100{,}000 for the original 2D AnyUp), with the $T\!=\!8$ curriculum stage never reached.

\textit{car-shadow} is a smaller case of limited headroom: bilinear's baseline score there ($0.522$) is already among the highest in the set.

\section{Experiment 4: Model Size and Inference Cost}
\label{sec:cost}

Experiments~1--3 establish that AnyUp3D produces more temporally consistent and more downstream-useful features than its frame-independent counterpart.
They say nothing about what that improvement costs.
This experiment quantifies the price of the temporal extension along three axes: parameter count, inference latency, and peak GPU memory, each measured directly rather than estimated.

Real-time operation is explicitly out of scope for this project (Chapter~3, Non-Functional Requirements); the purpose here is not to demonstrate that AnyUp3D is fast, but to establish concretely how much slower and larger it is than the 2D baseline, so that the temporal-consistency gains of Experiment~2 can be read against a known cost.

% ── 4.5.1 Setup ──
\subsection{Setup}

Both models were instantiated with the architecture configuration used throughout this chapter: query/key dimension $d_{qk} = 128$, four attention heads, a spatial convolution kernel of size~$1$, an LFU kernel of size~$5$, and a spatial window ratio of $0.1$.
AnyUp3D was additionally configured with a temporal convolution kernel $t_k = 3$ and a temporal attention window $w_t = 4$, matching the trained model evaluated in Experiments~1--3.

\paragraph{Freshly initialised weights.}
Both models were benchmarked without loading trained checkpoint weights.
This is methodologically appropriate: parameter count, latency, and memory consumption are properties of the computational graph and of tensor shapes, not of the numerical values stored in the weights.
A trained and an untrained model of identical architecture cost exactly the same to run.
The corollary is that this experiment measures compute cost only, and says nothing about accuracy per unit of compute.

\paragraph{Synthetic inputs.}
Timing used synthetic random tensors shaped to match the real evaluation pipeline rather than actual DAVIS clips: a guide video at $224 \times 224$, a low-resolution feature volume at $14 \times 14$ (VideoMAE ViT-B/16's patch grid), $768$ feature channels (VideoMAE-base hidden size), and clips of $T = 8$ frames.
This is a deliberate choice.
Feeding real clips would fold data loading and VideoMAE feature extraction into every measurement, and both are shared by all three upsampling conditions; synthetic inputs isolate the cost of the upsampling architecture itself, which is the quantity of interest.
Measurements were taken on the same T4-class GPU used throughout this chapter.

\paragraph{What is being compared.}
The comparison follows the frame-independent baseline definition already established in Section~\ref{sec:setup}: the 2D~AnyUp baseline is the pretrained 2D model applied once per frame.
Accordingly, the timed operations were:

\begin{itemize}
    \item \textbf{2D AnyUp:} a loop of $T = 8$ forward calls, each on single-frame tensors of shape $(1, 3, 224, 224)$ and $(1, 768, 14, 14)$ --- the actual cost of deploying the 2D baseline over a video clip.
    \item \textbf{AnyUp3D:} a single forward call on the full spatiotemporal volume, $(1, 3, 8, 224, 224)$ and $(1, 768, 8, 14, 14)$.
\end{itemize}

Reporting the 2D baseline as a per-clip loop rather than a per-frame call is what makes the two numbers comparable: both then describe the cost of upsampling one eight-frame clip.

\paragraph{Measurement protocol.}
Parameter counts were obtained by summing \texttt{numel()} over \texttt{model.parameters()}, and static size by summing $\texttt{numel()} \times \texttt{element\_size()}$ under \texttt{float32} ($4$ bytes per parameter).
Registered buffers (non-trainable persistent tensors) were measured separately and found to be empty for both models, so all static cost is attributable to learnable weights.

Latency was measured under \texttt{torch.no\_grad()} at batch size~1, the standard convention for reporting inference latency.
Five warm-up iterations were discarded before timing, to exclude CUDA kernel compilation and caching effects, followed by 20 timed iterations.
Each timed region was bracketed by \texttt{torch.cuda.synchronize()}: CUDA operations are asynchronous, so without explicit synchronisation a host-side timer measures kernel \emph{launch} time rather than GPU compute time.
Mean and standard deviation across the 20 iterations are reported.

Peak memory was measured with PyTorch's \texttt{max\_memory\_allocated()} function.
Before each run, \texttt{reset\_peak\_memory\_stats()} cleared residual allocations so that each model's peak was measured independently.

\paragraph{Query chunking.}
At full resolution, AnyUp3D's cross-attention operates over $T \times H \times W = 8 \times 224 \times 224 = 401{,}408$ query tokens jointly, which exhausted the available GPU memory on a first attempt.
This was resolved using the model's built-in query chunking (Chapter~3, Section~\ref{sec:crossattn3d}), which computes attention over non-overlapping query chunks against the full key and value sequences, reducing the peak attention-matrix footprint from $\mathcal{O}(Q \cdot K)$ to $\mathcal{O}(q_{\text{chunk}} \cdot K)$.
A chunk size of $q_{\text{chunk}} = 50{,}176$ was used --- exactly one frame's worth of queries.
All AnyUp3D figures below are therefore reported \emph{with} chunking enabled; the unchunked model does not fit on this hardware at this resolution.

% ── 4.5.3 Analysis ──
\subsection{Analysis of Inference Cost}
\label{sec:cost-analysis}

The two halves of this result tell different stories, and the gap between them is the finding worth stating.

The parameter increase is modest and architecturally accounted for.
The extra $662{,}656$ weights come almost entirely from extending the 2D convolutions to 3D --- a temporal kernel of $t_k = 3$ where the 2D model is effectively of extent~1 along time --- together with the additional temporal-axis machinery in RoPE3D and CrossAttention3D.
A $1.75\times$ parameter count is a small price for temporal modelling capability, and it is roughly what one would predict from the architectural changes alone.

The latency and memory costs are disproportionately larger than the parameter growth predicts, and the reason is structural rather than incidental.
AnyUp3D computes attention jointly over all $T \times H \times W$ spatiotemporal query tokens in the clip, whereas the 2D baseline's eight independent calls each attend only within one frame's much smaller token set.
Attention cost scales worse than linearly in sequence length, so processing a clip ``all at once'' costs more than the sum of eight small independent passes --- even though it avoids the per-call dispatch overhead of invoking the model eight times.
The $10.6\times$ memory factor has the same origin: the attention matrix, not the weights, dominates the footprint, which is precisely why query chunking was required to run the model at all at this resolution.

This is worth stating plainly, because the cost and the benefit are the same mechanism.
The joint spatiotemporal attention responsible for the $2.7\times$ slowdown and the $10.6\times$ memory increase is the same computation responsible for the $+0.081$ mean temporal-consistency improvement reported in Experiment~2 (Section~\ref{sec:temporal}) --- features are more temporally stable precisely \emph{because} adjacent frames attend to one another rather than being upsampled in isolation.
The measured overhead is therefore not an implementation inefficiency to be optimised away without consequence; it is the direct computational expression of the design decision under evaluation.
Reducing it would require changing that mechanism --- for example, replacing dense spatiotemporal attention with linear or sparse windowed attention --- rather than merely tuning the existing implementation.

\section{Discussion and Limitations}
\label{sec:discussion}

% ── 4.5.1 Summary of Findings ──
\subsection{Summary of Findings}
\label{sec:discussion-summary}

The three experiments present a broadly consistent, positive picture of AnyUp3D's capabilities, with one clear direction remaining for future work.
The training convergence analysis (Experiment~1) confirms that the 3D extension does not regress on the spatial upsampling quality inherited from 2D initialisation, and shows early signs of improvement.
The temporal consistency evaluation (Experiment~2) demonstrates that AnyUp3D produces substantially more stable features than frame-independent 2D upsampling, with improvements on all 30 DAVIS clips and a mean cosine similarity increase of $+0.081$.
The downstream evaluation (Experiment~3) extends this positive result to a practical task: under non-parametric label propagation, a training-free protocol with no learned head, AnyUp3D improves the weighted $\mathcal{J}\&\mathcal{F}$ score from $0.266$ to $0.347$ ($+0.081$) over bilinear upsampling (Table~\ref{tab:jf-agg}), with a matching unweighted per-clip mean improvement of $+0.074$ across 27 of 30 clips (Table~\ref{tab:jf-perclip}).
Notably, this gain is achieved using Video Swin-T features, a backbone AnyUp3D was never fine-tuned on, as a deliberate zero-shot test of the architecture's backbone-agnostic design.
Experiment~4 (Section~\ref{sec:cost}) prices these gains: AnyUp3D carries $75.5\%$ more parameters than the 2D baseline, but runs $2.7\times$ slower and consumes $10.6\times$ more peak GPU memory on an eight-frame clip.
The disparity between the modest parameter growth and the much larger runtime cost is itself informative --- it localises the expense in the joint spatiotemporal attention rather than in the added weights, which is the same mechanism producing the temporal-consistency gain above.
The open question is how much further this margin would grow with a completed $T$-curriculum and backbone-matched fine-tuning, neither of which the available training budget permitted (Section~\ref{sec:discussion-limitations}).

% ── 4.5.2 Limitations ──
\subsection{Limitations}
\label{sec:discussion-limitations}

Several limitations qualify how far these results can be generalized.

\paragraph{Zero-shot backbone transfer only.}
AnyUp3D was fine-tuned exclusively on VideoMAE features, but Experiment~3 evaluates it on Video Swin-T features it has never seen.
The reported $+0.081$ gain is therefore a zero-shot transfer result, not the ceiling of what AnyUp3D could achieve on a backbone it was actually fine-tuned on.
It should be read as a lower bound on the model's potential with Swin-T, not the model's best-case performance.

\paragraph{No spatial-only benchmark.}
The original evaluation plan included a linear probing experiment on a standard image segmentation dataset (e.g., ADE20K) to measure spatial upsampling quality in isolation, using mIoU (mean Intersection-over-Union) as the metric.
This experiment was not conducted due to time constraints.
Instead, Experiment~1 provides qualitative evidence of spatial quality through PCA visualization, and Experiment~3 provides indirect quantitative evidence: the $\mathcal{F}$-score (contour accuracy) improves by $+0.105$, nearly double the $\mathcal{J}$-score (region overlap) improvement of $+0.058$, suggesting a specifically spatial contribution.
A dedicated spatial benchmark would still strengthen the evaluation by isolating spatial quality independent of temporal effects.

\paragraph{No ablation study.}
We do not present ablation experiments isolating the contributions of the two main 3D components.
The two most informative ablations would be: (1)~removing the 3D convolutions and stacking 2D convolution outputs along the temporal axis before passing them to the 3D attention, to isolate the contribution of the attention; and (2)~removing the 3D attention and applying the 3D convolutions independently per-frame in a loop, to isolate the contribution of the temporal convolutions.
Such ablations would clarify how much of the temporal consistency gain is attributable to each component.

\paragraph{Single training run.}
All results are reported from a single training run rather than averaged over multiple seeds.
The temporal consistency results are robust (improvements on all 30 clips suggest the result is not seed-dependent), and the Experiment~3 gain holds under both weighted and unweighted aggregation, which reduces the likelihood of a chance result; but neither metric is supported by confidence intervals from repeated runs.

\paragraph{Scope of the inference benchmark.}
The cost measurements in Experiment~4 were taken on synthetic random tensors shaped to match the real pipeline, not on DAVIS clips run end-to-end through VideoMAE.
This isolates the upsampler's cost cleanly but excludes data loading and backbone feature extraction, so the reported figures are not end-to-end pipeline latency.
Only a single query chunk size was tested; the chunk size trades memory against speed, and that trade-off curve was not swept.
Measurements were taken on one GPU class (T4) at batch size~1, and would differ on other hardware or under batching.

\paragraph{Incomplete training budget.}
The model was trained for 6{,}000 steps, compared to 100{,}000 steps for the original 2D~AnyUp~\cite{anyup}, and reached only the $T\!=\!4$ stage of the planned $T\!=\!2/4/8$ curriculum.
That AnyUp3D already improves downstream segmentation under these conditions, and on a backbone it was never fine-tuned on, suggests the current results likely understate its potential.
Completing the $T\!=\!8$ curriculum stage and training to convergence remains the most direct path to closing the remaining gap with the original 2D AnyUp.

\paragraph{Absolute $\mathcal{J}\&\mathcal{F}$ scores.}
The mean $\mathcal{J}\&\mathcal{F}$ scores reported ($0.266$ for bilinear, $0.347$ for AnyUp3D) are well below dedicated video object segmentation methods, which combine learned matching networks with dedicated VOS training and typically exceed $0.80$ on DAVIS~2017.
This is expected: label propagation on frozen, generic video-encoder features with no trainable component is a much simpler baseline than purpose-built VOS methods, and the comparison here is relative (AnyUp3D vs.\ bilinear under identical conditions), not absolute.
